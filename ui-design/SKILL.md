This skill guides creation of exceptional frontend interfaces for any coding assistant, IDE, or model. It is vendor agnostic and focused on outcomes: beautiful, usable, shippable UI.

The user provides frontend requirements: a component, page, application, admin panel, dashboard, marketing site, mobile web UI, or internal tool. They may include audience, brand direction, stack, or technical constraints.

## Core Mission

Build interfaces people want to keep open.

Not just "looks good in a screenshot."
Not just "technically correct."

Create products with personality, clarity, and strong UX instincts.

Every output should feel like it belongs to a real company with taste.

## Product Taste Standards

Design with the same instincts found in polished products like niche SaaS tools, thoughtfully built internal systems, premium consumer apps, and founder-led software.

Aim for interfaces with:

- Clear hierarchy
- Strong information density without clutter
- Confident spacing
- Excellent defaults
- Sharp typography choices
- Subtle delight
- Fast comprehension
- Real-world usability
- Consistent visual systems
- Distinct personality

Avoid "template energy."

## Before Writing Code: Think Like a Designer

First understand:

### 1. Purpose

What job does this UI perform?

- Decision making?
- Monitoring?
- Input-heavy workflows?
- Browsing?
- Habit tracking?
- Admin control?
- Consumer delight?

Design should serve the job.

### 2. User Reality

Who uses this?

- Executive on laptop?
- Ops person in tabs all day?
- Mobile consumer?
- Power user with keyboard shortcuts?
- Hobbyist enthusiast?
- First-time visitor?

Respect their context.

### 3. Desired Feel

Pick a deliberate aesthetic direction. Commit fully.

Examples:

- Quiet luxury
- Industrial utility
- Editorial intelligence
- Dark command center
- Warm analog craftsmanship
- Retro terminal modernized
- Rugged field tool
- Scientific precision
- High-trust financial
- Playful tactile
- Elegant minimalism
- Dense operator cockpit

Choose one. Execute cleanly.

### 4. What Makes It Memorable?

Define one standout trait.

Examples:

- Incredible typography
- Unusual navigation rhythm
- Signature motion system
- Striking data cards
- Warm material palette
- Brutally efficient layout
- Premium dark mode
- Beautiful empty states
- Distinctive filtering UX

If everything is special, nothing is.

## UX Standards

The interface must work in the real world.

### Navigation

- Obvious orientation
- Fast movement between sections
- Consistent placement
- Supports growth over time

### Forms

- Clear labels
- Helpful defaults
- Inline validation
- Proper keyboard behavior
- Accessible focus states

### Tables / Lists

- Scannable rows
- Strong alignment
- Useful density
- Sorting/filtering/search that feels immediate

### Dashboards

- Real hierarchy
- Metrics with context
- Trend visibility
- Actionable surfaces, not decorative charts

### Empty States

- Useful, motivating, informative
- Show what to do next

### Errors

- Calm, specific, fixable

## Visual Direction Rules

### Typography

Use type with taste and contrast.

Avoid overused defaults unless specifically requested.

Prefer pairings such as:

- Distinctive serif + restrained sans
- Technical mono + clean grotesk
- Humanist sans + elegant display

Use scale intentionally.

### Color

Build a real palette, not random accents.

Use:

- Dominant base tone
- Secondary support tones
- 1 sharp accent color
- Semantic success/warn/error states

Strong monochrome + one accent often beats rainbow UI.

### Spacing

Spacing is design.

Use rhythm systems (4 / 8 / 12 / 16 / 24 / 32 etc.)
Let sections breathe. Compress where speed matters.

### Depth

Prefer subtle layers:

- soft shadows
- borders
- translucent panels
- matte surfaces
- restrained gradients
- texture where appropriate

### Icons

Consistent weight and style. Never random icon soup.

## Motion Standards

Use motion with intent.

Good uses:

- Entry sequencing
- Hover confidence
- State transitions
- Expanding panels
- Drag feedback
- Loading polish

Avoid gimmicks.

Fast, smooth, understated beats flashy chaos.

Use CSS transitions or native animation libraries depending on stack.

## Layout Intelligence

Choose layout based on workflow.

### Dense Productivity UI

Use:

- side nav
- sticky headers
- split panes
- command bars
- resizable regions

### Consumer / Content UI

Use:

- immersive hero areas
- card rhythm
- strong imagery
- progressive disclosure

### Dashboard UI

Use:

- asymmetric grids
- mixed card sizes
- priority placement
- quick actions near metrics

Break rigid grids when useful.

## Code Quality Standards

All output must be production-grade.

### Required

- Clean component structure
- Reusable patterns
- Responsive behavior
- Accessible semantics
- Keyboard usability
- Reasonable state handling
- Maintainable styling
- Sensible naming
- No dead code

### Preferred

- Design tokens / CSS variables
- Reusable primitives
- Theme support
- Loading / empty / error states
- Dark mode if relevant

## Framework Behavior

Adapt to requested stack.

### React / Next / SPA

Use component architecture, clean state patterns, motion libraries when available.

### HTML/CSS/JS

Ship complete working UI with polished vanilla interactions.

### Vue / Svelte / Others

Use idiomatic patterns for framework.

### Tailwind

Use disciplined utility composition, not class soup.

## Specialty Modes

### Internal Tool Mode

Optimize speed, density, clarity, repetitive workflows.

### Founder SaaS Mode

Polished, lean, trust-building, conversion aware.

### Enthusiast App Mode

Personality-rich. Designed for people who care deeply.

### Data Product Mode

Legibility first. Clear relationships. Excellent filtering.

### Mobile Mode

Thumb-friendly, layered navigation, high clarity.

## Anti-Patterns (Never Do This)

- Generic startup landing page look
- Purple gradient on white for no reason
- Random cards everywhere
- Excessive rounded blobs
- Weak typography
- Empty whitespace with no hierarchy
- Over-animated nonsense
- Fake dashboard metrics with no meaning
- Three fonts fighting each other
- Tiny low-contrast text
- Components pasted together with no system
- "AI generated" sameness

## If User Gives Minimal Prompt

If asked "build a dashboard" or similar:

- Infer likely audience
- Pick bold direction
- Create complete UX structure
- Add realistic details
- Deliver something worth shipping

Do not wait for hand-holding.

## If User Gives Existing Brand Examples

Extract patterns such as:

- tone
- spacing density
- hierarchy
- palette
- typography mood
- navigation model
- surface treatment

Then reinterpret, don't clone.

## Output Expectation

Produce code that makes an experienced product builder think:

> "Yeah… somebody actually cared."

Not generic.
Not sterile.
Not demo bait.

Real software energy.

## Final Principle

**Taste is a feature.**

Use judgment, restraint, boldness, and craftsmanship in equal measure.
